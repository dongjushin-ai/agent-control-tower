## ① 문제 정의

| 항목 | 내용 |
| --- | --- |
| 대상 | 사람 없이 도는 에이전트를 1~20개 운영하는 개인 개발자·1인 운영자. Claude Code 클라우드 예약 작업·`claude -p` cron·GitHub Actions 안의 에이전트·다른 LLM 에이전트·일반 cron 스크립트를 섞어 씀. 서버를 따로 운영하고 싶지 않음 |
| 문제 인식 | 결과가 실행마다 흩어져 있고, 특히 **아예 안 돈 실행**은 아무 흔적도 남기지 않아서 늦게 알아요 |
| 원하는 것 | 하루 한 번 1~2분 안에 "뭐가 깨졌나 / 이번 주 얼마나 잘 돌았나"를 확인하고, 조용히 죽은 에이전트는 하루 안에 알림으로 알기 |
| 관찰되는 현상 | ① 만든 사람이 직접 겪은 일: 매시간 돌아야 하는 에이전트가 이틀 넘게 멈춰 있었는데 알려 주는 곳이 없었음 (개인 MVP를 만든 계기). ② 경쟁 도구(ccmon, agents-observe, Claude-Code-Agent-Monitor, CCDash 등)는 대부분 **내 컴퓨터에서 도는 Claude Code 세션**을 실시간으로 보거나 비용을 봄. 클라우드·예약 실행은 대상이 아님. ③ healthchecks.io 같은 cron 모니터는 "안 돈 것"은 잡지만 SaaS 계정이나 서버가 필요하고, 에이전트의 "부분 성공·요약·결과 링크"를 모름 |
| 기대 효과 | 서버 없이 `init` 한 번 + 프롬프트 끝 지시문으로 시작. 침묵 감지 24시간 이내, 확인 2분 이하. 오픈소스로는 "클라우드 에이전트용 데드맨 스위치"라는 빈자리 선점 |

**포지셔닝 한 줄**: "로컬 세션 모니터는 키보드 앞에 있을 때, Agent Control Tower는 자리에 없을 때."

## ③ MVP 범위와 백로그

**MVP (스프린트 1, 이번 커밋)**

- 범용 CLI (`npx agent-control-tower`): `init`(설정·폴더·워크플로), `log`(검증·비밀 차단·`--push` 재시도), `run`(명령 감싸기), `status`(텍스트·JSON·마크다운, 종료 코드 2), `build`(정적 사이트), `serve`(로컬)
- 정적 대시보드: 상태 카드·7일 막대·성공률·기록률·끊김 경고, 다크 모드(시스템+토글), 영어/한국어, 데모 데이터(`?demo`, 가짜라고 표시), 외부 요청 0
- GitHub Actions 템플릿: 감시 워크플로(비공개 저장소 OK), Pages 배포 워크플로
- 지시문 조각: Claude Code(영·한), 다른 LLM 에이전트(셸 도구/감싸기/node 없이), cron·systemd·GitHub Actions
- 비공개 저장소 안내 (토큰 없이 쓰는 3가지, 하지 말 것)
- README(영어) + README.ko.md, MIT, 경쟁 비교표, 스크린샷, 테스트 41개 + CI

**개인 버전에서 걷어낸 것**: 특정 에이전트 전용 로그 어댑터와 규칙, 개인 작업-id·저장소 주소, KST 고정(→ 설정 `timezone`), 한국어 고정(→ en/ko), Pretendard CDN(→ 외부 요청 0)

**백로그**

- `doctor`: 저장소 권한·push·설정을 한 번에 점검
- cron 식 일정 (`"0 2 * * *"`) — "08:52 실행이 09:30까지 안 옴" 같은 정밀 판정
- 지표(metrics) 작은 선 그래프, 30일 보기
- 알림 확장: 워크플로에서 Slack/Discord/ntfy 웹훅 (비밀값은 Actions secret)
- 어댑터: GitHub Actions 실행 기록 읽기, 텍스트 로그(`cycles.log` 형식) 정규식 어댑터
- 동시 신규 작업 등록 시 `tower.config.json` rebase 충돌 자동 해결
- 리포트 공유용 배지(SVG) — README에 "agents: 5/5 healthy"
- 1분 설치 GIF, 데모 영상
